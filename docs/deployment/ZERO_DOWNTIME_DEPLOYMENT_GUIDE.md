# GenioAI Backend 最小停机部署指南（滚动更新）

## 📋 概述

本指南介绍如何使用**滚动更新（Rolling Update）**策略实现 GenioAI Backend 的最小停机部署。

## 🔄 部署策略对比

| 特性 | 传统部署 (deploy.sh) | 滚动更新 (deploy-zero-downtime.sh) |
|------|---------------------|----------------------------------|
| 停机时间 | ⚠️ 长（约 1-2 分钟） | ✅ 极短（约 5-10 秒） |
| 用户影响 | 部署期间服务完全不可用 | 短暂中断，快速恢复 |
| 回滚速度 | 需要重新构建镜像（慢） | 加载备份镜像（快） |
| 资源占用 | 低（单容器） | 低（单容器，构建时临时增加） |
| 复杂度 | 简单 | 简单 |
| 配置要求 | 无特殊要求 | 无特殊要求 |
| 适用场景 | 开发/测试环境 | 测试/生产环境 |

## 🏗️ 工作原理

### 滚动更新流程

```
┌──────────────────────────────────────────────────────────┐
│ 1. 旧容器运行中 → 拉取代码 → 构建新镜像                    │
│    (服务正常运行，用户无感知)                              │
└──────────────────────────────────────────────────────────┘
                           ↓
┌──────────────────────────────────────────────────────────┐
│ 2. 停止旧容器 → 启动新容器                                 │
│    (短暂停机 5-10秒)                                      │
└──────────────────────────────────────────────────────────┘
                           ↓
┌──────────────────────────────────────────────────────────┐
│ 3. 健康检查 → 服务恢复                                    │
│    (用户可以继续访问)                                      │
└──────────────────────────────────────────────────────────┘
```

### 关键优化点

相比传统部署，滚动更新的优化：

1. **构建时不停机** - 在旧容器运行时构建新镜像（节省 1-1.5 分钟）
2. **快速切换** - 停止旧容器后立即启动新容器（5-10秒）
3. **自动回滚** - 失败时可快速加载备份镜像

## 📝 使用说明

### 基本命令

```bash
# 执行滚动更新部署
./deploy-zero-downtime.sh

# 查看服务状态
./deploy-zero-downtime.sh --status

# 查看实时日志
./deploy-zero-downtime.sh --logs

# 回滚到上一个版本
./deploy-zero-downtime.sh --rollback

# 显示帮助信息
./deploy-zero-downtime.sh --help
```

## 🎯 核心优势

### 1. 最小停机时间

- 构建镜像时服务继续运行（节省 1-1.5 分钟）
- 只在容器切换时短暂停机（5-10秒）
- 总停机时间减少 90%+

### 2. 简单易用

- 不需要 Nginx 或负载均衡器
- 不需要额外的配置文件
- 与传统部署同样简单

### 3. 快速回滚

```bash
./deploy-zero-downtime.sh --rollback
```

- 自动加载备份镜像
- 快速恢复服务
- 无需重新构建

### 4. 资源友好

- 不需要同时运行两个应用容器
- 只在构建时临时占用额外资源
- 适合资源有限的服务器

## ⚠️ 注意事项

### 1. 停机时间

虽然停机时间很短（5-10秒），但仍有短暂中断：
- 请求会被拒绝或超时
- WebSocket 连接会断开
- 建议在低峰期部署

### 2. 数据库迁移

如果更新包含数据库迁移：

**向后兼容的迁移（推荐）**：
```bash
# 先执行迁移
docker exec genio-backend /app/genioAI_server migrate

# 再执行部署
./deploy-zero-downtime.sh
```

**不兼容的迁移**：
```bash
# 使用传统部署（允许停机）
./deploy.sh
```

### 3. 资源要求

最低配置：
- CPU: 2-4 核
- 内存: 4-8GB
- 磁盘: 20GB+ 可用空间

建议配置：
- CPU: 4-8 核
- 内存: 8-16GB
- 磁盘: 50GB+ 可用空间

## 🔍 故障排查

### 部署失败

**症状**: 新容器健康检查失败

```bash
# 查看容器日志
./deploy-zero-downtime.sh --logs

# 或者手动查看
docker logs --tail=100 genio-backend
```

**解决方案**：
1. 检查应用日志中的错误信息
2. 验证环境变量配置（.env 文件）
3. 确认数据库和 Redis 连接正常
4. 检查磁盘空间和内存资源
5. 如需回滚：`./deploy-zero-downtime.sh --rollback`

### 服务无法访问

**症状**: 部署后服务不响应

```bash
# 检查容器状态
docker ps | grep genio-backend

# 检查端口监听
netstat -tlnp | grep 8200

# 测试本地连接
curl http://localhost:8200
```

### 回滚失败

**症状**: 回滚命令执行失败

```bash
# 检查备份文件
ls -lh /opt/genio-backend-backups/

# 如果没有备份，使用传统部署重新部署稳定版本
git checkout <stable-version>
./deploy.sh
```

## 🔐 生产环境建议

### 1. 在低峰期部署

即使只有 5-10 秒停机，也建议：
- 在用户最少的时间段部署
- 提前通知相关人员
- 准备好回滚方案

### 2. 预先测试

在生产环境部署前：
```bash
# 在测试环境先测试
./deploy-zero-downtime.sh

# 验证功能正常
curl http://localhost:8200/health

# 检查日志无错误
docker logs --tail=50 genio-backend
```

### 3. 监控部署

部署时监控关键指标：
```bash
# 监控容器状态
watch -n 1 'docker ps | grep genio'

# 监控服务响应
watch -n 1 'curl -s -o /dev/null -w "%{http_code}\n" http://localhost:8200'

# 监控日志
docker logs -f genio-backend
```

### 4. 准备回滚

确保可以快速回滚：
```bash
# 检查备份是否存在
ls -lh /opt/genio-backend-backups/

# 熟悉回滚命令
./deploy-zero-downtime.sh --rollback
```
